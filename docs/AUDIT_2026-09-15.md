# Audit — 2026-09-15

A full read of every doc, code file and test, followed by measured fixes. Each claim
in the docs was checked against what the code actually does; where they disagreed,
the code was measured, then fixed or the doc corrected, then re-measured on both pairs.

**Verification standard used throughout**
- A regression snapshot (3 exit configs × 2 pairs, full trade lists) was taken before
  any change. After the behaviour-neutral refactors (UTC timestamps, shared helpers,
  config, bookkeeping) every config reproduced **trade-for-trade**.
- Every historical row in `docs/RESULTS.md` (Baseline, A, B1–B4, E) was re-run with a
  one-line command and matched the recorded numbers exactly. Two rows that didn't match
  (B3b, D) were explained and the explanation itself verified by reproducing the old
  numbers exactly.
- New behaviour got tests, including negative controls that prove the checks can fail.
- The dashboard was driven end-to-end with Streamlit's `AppTest` (backtest + paper live
  order); all three compose files validate with `docker compose config`.
- Test suite: 163 → **210 passing** (2 network tests deselected by default).

## Addendum — live-path fixes (2026-09-17)

A review of the sibling production system (`docs/GADEL_ENGINE_COMPARISON.md`) exposed
five defects in our MT5 handler that only a real broker would have revealed. All are
fixed; none touches the backtester, and the same regression snapshot confirms all six
configs still reproduce trade-for-trade. **218 tests pass.**

| Finding | Fix | Evidence |
|---------|-----|----------|
| Fill mode hardcoded to IOC; HFMarkets (the broker in our `.env`) accepts **FOK only** and rejects IOC with retcode `10030` — our first live order would have bounced | read the symbol's `filling_mode` bitmask and request a supported mode, falling back to RETURN | `test_fill_mode_follows_what_the_symbol_accepts` |
| The MetaTrader5 library binds the terminal to the thread that called `initialize()`, but our RPC server answers each request on a **new** thread — the second order would have failed | all handler work funnelled onto one pinned worker thread; `ping` still answers outside it | `test_all_mt5_calls_run_on_one_thread` |
| Orders carried no magic number, so MT5 reported them as magic 0 — indistinguishable from trades the account owner places by hand, and closable by us | `MT5_MAGIC_NUMBER` stamped on every order; positions filtered to ours (`MT5_ONLY_OWN_POSITIONS`); closing a foreign position refused | `test_orders_carry_our_magic_number`, `test_positions_exclude_hand_placed_trades`, `test_close_refuses_a_position_we_did_not_open` |
| Broker rejections surfaced as bare numbers | 10016/10018/10019/10027/10030 return a readable reason | `test_rejection_explains_the_broker_code` |
| A stored trailing space in a server name breaks login with a misleading error | login and server whitespace-stripped | `test_credentials_are_whitespace_stripped` |
